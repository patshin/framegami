# ADR-001 — Actual frontend implementation

Date: 2026-10-17
Status: Implemented technical variance; not a claim that the earlier stack was used.

The product proposal recommended Astro + React + TypeScript. During implementation,
package retrieval was unavailable in the authoring environment. Rather than ship
unexecuted framework scaffolding, this delivery implements the same static-product
boundaries with plain browser JavaScript/CSS and a zero-dependency Node compiler.
`src/schema.d.ts` is a type contract; the app itself is JavaScript, not a compiled
TypeScript/React application.

Benefits: the complete preview opens as one file, no install is required for the
build, no runtime CDN or backend exists, all 439 routes are generated, and pure
logic can be tested with Node's built-in runner.

Trade-offs: no React component ecosystem, no Astro integrations, and static rendering
is maintained by a small custom builder. Any future migration should consume the
same catalog and core prompt compiler, not create a second content model or erase
the evidence gate. Framework migration is optional work, not silently declared done.

This changes implementation technology, not the agreed absence of paid services,
API key collection, accounts or generation calls.
